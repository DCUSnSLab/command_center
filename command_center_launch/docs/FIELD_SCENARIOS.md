# 실외 주행 실험 시나리오 4종 (2026-08-11 작성)

이전 필드·챔버 **로그에서 측정된 사실**에서 출발해, 각 시나리오가 무엇을
닫는지(어느 미검증 항목/결함의 재발 여부)를 명시한다. 절차의 공통 부분은
`FIELD_PROCEDURE.md`(2026-08-06 판)를 따르고, 이 문서는 시나리오별 차이만
적는다.

**공통 안전 수칙** — 전 시나리오 동일:
- RC 조종자는 상시 개입 가능 상태를 유지한다(자율 중에도 조종기 파지).
- 연석 1 m 이내 접근이 보이면 수동 개입 후 상황 기록 — 개입 자체가 데이터다.
- `[BLOCKED] assist requested` 발생 시 즉시 정지 확인 → 주변 확인 후 RC 회수.
  (챔버 실측: 막힘 시 에스컬레이션이 정상 발동한다 — 8/11 hard 판 3/3)
- RC 링크 플래핑(8/4 실측 33회/60초) 징후가 보이면 조종기 거리를 줄이고
  기록에 남긴다 — 자율 창이 쪼개지면 그 런은 판정에서 제외.

**권장 수행 순서**: S4-간이(개활지 RTK 확인, ~5분) → **S1** → **S2** → S3 →
S4-전체(배터리 여유 시). S1·S2 가 이번 필드의 본론이고, S3 은 정지 작업이라
배터리 부족 시에도 가능, S4-전체는 다음 기회로 미뤄도 된다.

## S1 — 목표 도달 완결 (8/6 코스 재주행)

**무엇을 닫나**: 실차 목표 도달은 아직 한 번도 완결되지 않았다.

**실측 근거**:
- 8/6 오전: 낡은 합류 노드로 자율 전환 → 목표에서 **68.8 m** 미달.
- 8/6 오후: 합류 재선택 배포 후 재주행 → **16.1 m** 미달로 개선됐으나 미완.
- 그 후 배포된 변경: 비용 기반 합류의 접근 직선 통행성 검사(`c7d0bd5`),
  통과 이력 게이트(`2d2246c`) — 챔버 완주 3/3, 실차 미검증.

**절차**:
```bash
./field_bringup.sh --record \
  map_file_path:=/home/scv/MAP/D2/d2_unha.json \
  route_source:=sequential goal_node:=N026
```
1. yaw 게이트: RC 전진 ~10 m → `yaw autocal ENGAGED` 확인 (§2 공통 절차).
2. 자율 전환 → 개입 없이 관찰. 개입이 필요했다면 사유·좌표 기록 후 그
   지점부터 재전환(재전환도 데이터 — 재선택이 어떻게 동작하는지).

**측정·판정**:
- **합격**: `/goal_status` goal_reached (목표 1.5 m 이내, MPPI 임계).
- 부분: 최소 목표거리 < 16.1 m (8/6 오후보다 개선) — 정지 지점 좌표와
  behavior 로그의 마지막 상태를 반드시 기록.
- behavior 로그 확인 포인트: 합류 라인에 `+approach_clear` 태그가 보여야
  신형 코드다(구형은 `by min(approach+remaining)` 뿐). 8/6 오후 로그와
  같은 형식이면 **구버전이 도는 것** — 중단하고 빌드 확인.

## S2 — 이탈-재합류 A/B (통과 이력 게이트 실차 검증)

**무엇을 닫나**: 합류 규칙은 서로 반대 방향의 실패 둘을 겪었고, 수정은
챔버에서만 검증됐다. 실차 기하에서 두 방향 모두 확인한다.

**실측 근거**:
- 8/5: 최근접 합류가 경로 꼬리를 골라 목표 반대편으로 **18.8 m 역주행**.
- 8/6: RC 이동 중 합류가 낡아 전환 순간 뒤쪽 노드를 가리킴 (로그:
  `join idx 12→11→…→0` 으로 후퇴하는 재선택 흔적).
- 8/11 챔버: 최근접이 경로 끝이라 **경로를 통째로 건너뛰고** 지름길 시도,
  3/3 미도달 → 이력 게이트+접근검사로 0/6.

**절차** (같은 목표 N026, 두 런):

*(a) 경로 평행 이탈 — "따라잡기가 살아 있나"*
1. 기동 → 목표 전송 → 경로 확정 확인.
2. RC 로 **경로 옆 ~2 m 를 따라 20 m** 전진(8/6 재현 기하) → 자율 전환.
3. 판정: 전환 즉시 **전방** 노드로 합류(지나온 마지막 노드 +1 이내),
   경로 머리 방향 역주행 < 2 m. 역주행이 크면 8/5 형 회귀.

*(b) 경로 수직 이탈 — "건너뛰기가 막혀 있나"*
1. 경로 중간쯤에서 RC 로 **경로와 수직으로 5~6 m** 이탈 → 자율 전환.
2. 판정: 합류가 지나온 노드 +1 이내 — **경로 끝/멀리 앞 노드로 점프하면
   8/11 형 회귀**. 지름길 직선 주행이 보이면 즉시 개입.

**기록**: 두 런 모두 bag + behavior 로그. 전환 시각(초 단위)을 수기로도
남긴다 — 로그 대조 기준점.

## S3 — 전원 순환 자기 방위 재현성 (자기 앵커의 진짜 합격선)

**무엇을 닫나**: 8/5 자기 앵커 복원(HSI+ABSOLUTE)의 남은 미검증 항목 —
**전원 순환 후 같은 절대 방위로 복귀하는가**. FIELD_PROCEDURE §4 가 "이게
진짜 합격선"으로 명시한 그 실험이다.

**실측 근거**:
- 8/5: 세션 내 잔차 RMS 4.1~4.3° (안정) / **세션 간 span 23.6°**, 같은
  5 m 격자에서 30분간 11~21° 배회 — "±5° 상수"에는 못 미침.
- 8/6: yaw autocal 보정량 −6.4° 안팎에서 안정 (자기 앵커가 대략 맞는 상태).

**절차** (개활지 랜드마크에서, 다른 시나리오와 독립):
1. 랜드마크 지점에 차량 정렬 — 지면 표식(보도블록 모서리 등)에 앞바퀴와
   기수방위를 맞춘다. 사진 1장.
2. bag 기록 상태에서 RC 전진 ~10 m(직선) → 정지 → 후진 없이 그 자리 유지
   → 스택·차량 **전원 완전 순환** → 같은 표식에 재정렬 → 반복, **총 3세션**.
3. 각 세션: `yaw autocal ENGAGED` 까지만 확인하면 됨(자율 전환 불필요).
4. 판정은 현장이 아니라 bag 으로: `heading_eval2.py` — **엔코더 부호로
   전진 구간만** 게이트(8/5 에 후진 미게이트로 1회 오판했다).

**판정**:
- 3세션 방위 오프셋 span ≤ 5°: 자기 앵커 신뢰 — yaw 게이트 축소 논의 가능.
- span ≤ 10°: 조건부 — autocal 이 흡수 가능하나 게이트 유지.
- span > 10°: 8/5 상태에서 미개선 — ABSOLUTE 의존 금지 재확인, 게이트 필수
  유지. (어느 쪽이든 결론이 나온다 — 실패해도 실험은 성공이다.)

## S4 — GNSS 품질 노선 실측 → 챔버 존 역주입

**무엇을 닫나**: 챔버의 GNSS 열화 존은 전부 **합성**이다
(`zones/gps_canyon_20260803.yaml` 주석에 명시 — 근거 로그가 전 구간
status 0 이라 열화 구간을 특정할 수 없었다). 실측 열화 지도를 만들어
CHAMBER.md 의 "존 배치는 실측 열화 구간과 맞출 것" 규칙을 처음으로
충족시킨다.

**실측 근거**:
- 8/3 bag 3개: `/ublox_gps_node/fix` **전 표본 status 0** (RTK 미고정 —
  205159 는 24분 14,522표본 중 fixed 0, no-fix(-1) 8). 같은 날 다른
  2개 bag 은 아예 (0,0) 좌표(-1)만 기록.
- 8/4: status 2(σ≈2 cm) 관측됨 — 어느 위치/조건에서 잡히는지는 미기록.
- 8/4: RC 링크 플래핑 33회/60초 — 같은 bag 에서 재측정 가능.

**절차**:
*간이판 (도착 직후 ~5분)*: 개활지에서 정지 → `ros2 topic echo
/ublox_gps_node/fix` 로 status 2 도달 여부·소요 시간 기록. 이번 필드의
RTK 가용성 자체를 먼저 확정한다 — S1/S2 판정의 전제 조건.

*전체판 (배터리 여유 시)*:
1. `./field_bringup.sh --record --no-camera` (기록 전용, 자율 없음).
2. d2_unha 전 노선을 RC 저속(≤1 m/s)으로 일주. **랜드마크 3곳에서 각
   30초 정지** — 정적 기준점(위치 참값)이 있어야 σ 의 거짓말(liar cov,
   7/14 실측: 실오차 110 km 에 cov 0.14)을 잡는다.
3. 랩 복귀 후: `gps_quality_analysis.py`(차량 scv_sim_tools 에 있음)로
   구간별 status/σ/실오차 지도 생성.

**산출·판정**:
- 산출: 노선 위 열화 구간 좌표·크기 → `zones/*.yaml` 실측 갱신 +
  `design_chamber.py --emit-zone` 의 존 파라미터 보정.
- 판정 기준 없음(측량이므로) — 단, **RTK fixed 가 노선 어디에서도 안
  잡히면** 그 자체가 결론: 수신기/기지국 설정 점검이 다음 작업이 된다.
- 부수 측정: `/hunter_status` 로 RC 플래핑 카운트 재측정 (8/4 대비).
